# ZGM 前端 UI 优化说明

补充文档：

- [ZGM 前端分步接入记录](zgm_ui_steps_readme.md)

## 1. 文档范围

本文件记录 `codex/zgm-ranch` 分支中由 zgm 负责的本轮前端界面优化。

本轮正式代码改动集中在：

- `src/ui/Win32FarmApp.cpp`
- `assets/textures/terrain/`
- `assets/textures/ui/`
- `assets/textures/animals/`

本轮没有修改种植、养殖、订单、仓库、商店、工坊、存档等后端系统的规则和数据结构。前端继续通过项目原有公开接口读取状态并发起操作。

## 2. 优化目标

- 将各页面从简单功能面板调整为更符合农场游戏氛围的场景化界面。
- 统一顶部状态栏、导航栏、按钮、面板和提示信息的视觉语言。
- 提高文字与背景的对比度，减少黑色边框、绿色遮挡和装饰冲突。
- 保留背景可见区域，避免大面积不透明面板完全遮住农场场景。
- 改善页面切换时类似 PPT 的生硬感。
- 不改变后端接口含义、资源消耗、产出规则和存档逻辑。

## 4. 主要交互与后端接口

### 农田

前端读取土地视图，并调用现有种植接口：

- `TryPlantAt`
- `WaterPlot`
- `ApplyFertilizer`
- `Harvest`
- 土地扩建接口

界面支持选择土地、种植小麦/玉米/胡萝卜/番茄、浇水、施肥、收割和购买下一块土地。按钮可用状态由当前土地状态决定。

### 牧场

前端读取：

- `GetAllFacilities`
- `GetFacilityView`
- `GetAnimals`

前端当前提供：

- 建造牛棚和羊圈
- 购买鸡、牛、羊
- 当前设施批量喂食和批量收获
- 全牧场批量喂食和批量收获
- 设施容量、待喂养、生产中和可收获数量展示

动物图像只负责表现，实际数量和生产状态仍来自养殖系统。

### 饲料坊

前端读取工坊配方、队列和成品状态，并调用现有的开始生产与领取成品接口。鸡饲料和牛饲料的原料、加工时间及数量仍由后端规则决定。

### 订单

前端读取订单槽位、需求和奖励，并调用：

- `CompleteOrder`
- `AbandonOrder`

订单能否交付仍由后端库存校验决定。

### 仓库与商店

仓库页面展示玩家当前库存，并支持对选中物品执行单件出售。商店页面继续调用项目原有商品购买接口。购买、出售后的金币和库存变化由 `PlayerState` 及商店系统处理。

### 存档

前端保留：

- 手动保存
- 读取存档
- 自动保存状态展示

实际序列化、反序列化和自动保存时机仍由 `Game` 与持久化模块负责。

## 5. 公共 UI 实现

### 顶部状态区

顶部不再使用整条绿色横幅，而是拆分为多个信息块：

- 金币
- 等级与经验
- 游戏日期和时间
- 天气
- 当前速度

导航与时间控制保持原有功能，仅调整布局和视觉样式。

### 页面转场

页面切换时分别缓存旧页面和新页面，再进行约 320 毫秒的合成动画：

- 使用平滑缓动曲线控制透明度。
- 使用小幅位移增强方向感。
- 动画过程中只合成缓存帧，避免每一帧重新执行完整页面绘制。

### 消息提示

底部固定长条改为浮动提示：

- 宽度根据文本自动调整。
- 成功提示使用绿色强调色。
- 错误提示使用红色强调色。
- 支持淡入、停留和淡出。

## 7. 当前完成度与边界

### 已覆盖

- 主要页面都已有统一视觉风格和独立背景。
- 农田、牧场、饲料加工、订单交付、商店购买和存档读写的核心游戏流程可从 UI 操作。
- 页面切换、顶部状态、操作反馈和主要按钮状态已经完成统一优化。
- 本轮前端没有直接修改后端模块内部数据。

### 尚未完整暴露到 UI 的后端能力

以下能力后端已有接口，但当前界面没有独立入口，或只提供了简化操作：

1. 订单 `SetLocked()`：当前没有订单锁定开关。
2. 工坊 `ClaimAllProducts()`：当前主要使用单次领取入口。
3. 牧场 `FeedAnimal()`、`HarvestAnimal()`：当前以设施批量操作为主，没有逐只动物按钮。
4. `BuildFacility(ChickenCoop)`：已有默认鸡圈，但界面没有继续新建鸡圈的入口。
5. 购买/出售数量接口：后端可支持更灵活的数量，当前多数操作按固定数量执行。
6. 天气细节：当前显示天气类型，没有完整展示剩余持续时间及种植/养殖倍率。

因此，本版本可定义为“核心玩法前端已实现、主要页面视觉优化已完成”，但不应描述为“后端所有公开能力均已完整映射到 UI”。

猪圈和猪相关流程目前不列为本轮前端缺失项，因为项目后端的完整解锁、购买和产出链路尚未形成可直接接入的稳定流程。

## 10. 与队友后端版本合并

在合并其他队员的后端改动前，建议先提交本轮前端版本。随后拉取并合并后端分支，再重新编译检查接口是否变化。

若后端只修改 `src/core`、`src/ranch`、`src/order` 等模块，通常不会与本轮 UI 文件产生文本冲突；但公开接口签名或返回结构发生变化时，仍需要在 `Win32FarmApp.cpp` 中做对应适配。适配范围应限制在前端调用层，不改写队友的后端实现。
